## 规则

- 只修改这一个文件：`{{CONTRACT_PATH}}`。不要创建、删除或重命名任何文件。不要修改 brief。不要运行 git 命令，提交和推送由脚本完成。
- 只执行 `action` 为 `fix` 和 `delete` 的决定。`reject` 的条目不动。
- 改动要最小，只改决定里写到的地方。不要顺手重写其他章节。
- 改完之后，合同应当变短，或者长度基本不变。如果你发现必须明显加长才能完成，就不要改，直接说明原因并停止。
- 不要在合同里写修订历史、版本号或问题编号。历史在 git 和 PR 评论里。
- 不要写“完全消除”“严格保证”“绝不会”这类绝对的说法，除非合同里确实有机制保证它。
- 不要新增任何定时器、超时、锁、状态、字段、重试、组件或配置项。

改完后用一两句话说明改了什么。
